# دليل الإدارة

## الإعداد الأول

1. أنشئ مديرًا عبر `python -m app.cli create-admin`؛ لا توجد كلمة مرور افتراضية.
2. أضف صندوق بريد IMAP من لوحة المالك. استخدم كلمة مرور تطبيق عند توفرها، ولا تضعها في CSV أو الملاحظات.
   وعند تجهيز متغيرات `IMAP_HOST` و`IMAP_USERNAME` و`IMAP_PASSWORD` في `.env` يمكن تشغيل `python -m app.cli configure-mailbox` لحفظها مشفرة.
   لبريد Outlook الشخصي استخدم قسم **ربط Outlook عبر OAuth2** في الصفحة نفسها. بعد إعداد تطبيق Microsoft، اضغط زر الربط وسجّل الدخول ووافق على قراءة البريد؛ لا تلصق كلمة المرور أو Refresh Token في النموذج أو المحادثة.
3. قبل تمكين أي قالب جديد، راجع عينة بريد حقيقية مصرح بها، ثم أدخل ملف المطابقة. يجب أن يحوي `sender_domains` و`account_pattern`/`account_patterns` و`code_pattern`/`code_patterns` و`required_auth_result` و`sample_verified_at`. القالب الحالي يدعم الإنجليزية والإسبانية والبلغارية بقواعد منفصلة؛ لا ترفع ملف `.eml` أو رمزًا حقيقيًا إلى Git.
4. أضف حسابات المخزون أو استورد CSV، ثم أنشئ عميلًا وطلبًا وخصص الحساب.
5. من صفحة الطلب اضغط «إصدار» لعرض الرابط الموحد، ثم أرسله للعميل. يفتح العميل الرابط ويدخل رقم الطلب واسم المستخدم/المعرّف. الرقم مرجع خارجي غير مُتحقق منه ومفتاح استخدام محلي فقط؛ لا يحتاج العميل إلى تسجيل مسبق، ولا يستدعي هذا المسار Salla API أو البريد.

## الاستيراد

الملف UTF-8 وبالأعمدة التالية:

```csv
platform,account_identifier,mailbox_reference,status,notes
steam,steamuser123,main-imap,available,
ubisoft,ubisoft-alias,main-imap,available,inventory only
rockstar,rockstar-alias,main-imap,available,inventory only
```

المنصتان `ubisoft` و`rockstar` متاحتان لإدارة المخزون والتخصيص فقط. لا تُدخل كلمات مرور أو رموز مصادقة في المعرف أو الملاحظات، ولا يتصل الاستيراد بأي صندوق بريد لاستخراج رموز.

لا يؤكد النظام الدفعة عند وجود خطأ. التكرارات ضمن الملف أو مقابل المخزون تظهر برقم السطر.

## إعادة التخصيص

لا تعِد حسابًا مخصصًا تلقائيًا. أدخل سبب إعادة التخصيص؛ يلغي النظام رموز التفعيل وطلبات التحقق النشطة للتخصيص السابق ويسجل العملية. لا تغيّر حالة حساب مخصص يدويًا.

## التعامل مع الخطأ

`mail_profile_not_verified` يعني أن قالب Steam لم يثبت بعينة. `mail_timeout` يعني عدم العثور على تطابق مؤهل قبل المهلة. لا تعرض السجلات أو البريد للعملاء؛ راجع صندوق البريد والملف من حساب المالك فقط. القوالب الصينية والأوكرانية لا تُفعّل قبل فحص عينة مستقلة لكل لغة.

## صندوق إشعارات Salla المخصص (تكامل إداري منفصل)

1. لا تستخدم صندوق مخزون أو بريدًا شخصيًا. أنشئ أو اربط صندوقًا مستقلًا في **صناديق البريد** ثم افتح **تعديل**.
2. اختر الغرض **إشعارات Salla فقط**، وحدد المجلد الذي تصل إليه الإشعارات (مثل `INBOX` أو مجلد مخصص).
3. من رسالة Salla مصرح بها، أدخل نطاقات المرسل الموثوقة وأنماط عناوين الرسائل فقط. لا تضف نطاقًا واسعًا أو نمطًا مثل `.*`.
4. اضغط **اختبار اتصال القراءة فقط**. الاختبار لا يعرض الرسائل ولا يحفظ محتواها.
5. لا يصبح المسار جاهزًا إلا بعد وصول إشعار طلب مدفوع حقيقي واجتياز الاستيراد. المجلد لا يجب أن يحتوي على رسائل بطاقة أو إشعارات غير متعلقة بالطلبات.

هذه الخطوات تخص استيراد إشعارات Salla الإداري فقط، ولا تُستخدم لفتح جلسة `/salla` المبسطة. مسار `/salla` لا يقرأ الإشعار ولا يطلب بريد المشتري؛ يكتفي بمرجع خارجي غير مُتحقق وalias كبيانات وصفية عادية.

## ربط Outlook OAuth2

يحتاج السيرفر إلى `MICROSOFT_OAUTH_CLIENT_ID` و`MICROSOFT_OAUTH_CLIENT_SECRET` لتطبيق Microsoft واحد فقط، مع `MICROSOFT_OAUTH_TENANT=consumers` للحسابات الشخصية وRedirect URI مطابق تمامًا لـ`MICROSOFT_OAUTH_REDIRECT_URI`. الصلاحيات delegated هي `openid profile email offline_access Mail.Read` فقط، ولا يستخدم النظام `Mail.ReadWrite`. بعد موافقة المالك يحفظ النظام Refresh Token مشفرًا ويقرأ Graph قراءة فقط؛ لا يعلّم الرسائل كمقروءة ولا يحذفها. استخدم زر **إعادة تفويض Outlook** عند إبطال الموافقة؛ لا تلصق Refresh Token أو كلمة المرور في لوحة الإدارة.

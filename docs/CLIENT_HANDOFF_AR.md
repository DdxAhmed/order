# دليل تسليم OrderTrofy — نسخة العميل

هذا الدليل مكتوب لعبدالله، ولا يحتوي على كلمات مرور أو مفاتيح أو رموز وصول. إذا ظهرت قيمة سرية في لقطة شاشة أو رسالة، أوقف المشاركة واطلب تدويرها.

## 1) ما هو النظام؟

OrderTrofy بوابة ويب ولوحة إدارة تساعد المتجر على تنظيم مخزون المنصات، العملاء، الطلبات، وصناديق البريد. يوجد مسار عميل مبسّط وآمن يعتمد على **مرجع محلي** يكتبه المستخدم، ولا يتصل هذا المسار بـSalla للتحقق من الطلب.

المسار الحالي لا يطلب من العميل كلمة مرور أو رمز دخول أو رمز تحقق. لا يحتاج العميل إلى تسجيل يومي؛ يفتح الرابط ويدخل الحقول المطلوبة فقط. إدارة البريد والمخزون تتم من لوحة الإدارة.

## 2) الروابط

- الموقع: <https://ordertrofy.store/>
- بوابة المرجع المحلي: <https://ordertrofy.store/salla>
- لوحة الإدارة: <https://ordertrofy.store/admin/login>

لا تكتب كلمة مرور لوحة الإدارة في هذا الملف أو في رسائل العمل.

## 3) طريقة استخدام العميل

1. يفتح العميل `/salla`.
2. يكتب **Order Number / رقم الطلب**.
3. يكتب **Username / alias** (المعرّف الذي تريد ربطه بالجلسة).
4. يضغط «متابعة».
5. ينشئ النظام جلسة استخدام محلية مستقلة ويعرض حالة الجلسة.

يمكن أن يكون الرقم أي مرجع يدخله المستخدم، والنظام لا يتحقق منه عبر Salla. لذلك لا يُسمّى هذا الرقم «طلبًا موثّقًا» ولا يثبت ملكية شراء خارجي. المعرّف بيانات وصفية عادية وليس إثبات ملكية لحساب.

## 4) سياسة الاستخدام

- لكل `order_reference` عداد مستقل.
- الحد الافتراضي: 5 استخدامات ناجحة خلال نافذة متحركة مدتها 24 ساعة.
- مهلة بين الاستخدامات: 30 ثانية.
- الحماية تعمل داخل PostgreSQL مع idempotency وقفل للتزامن.
- يوجد Rate Limit ثانوي على الجلسة وعنوان IP.
- عند بلوغ الحد تظهر رسالة آمنة ولا يكشف النظام إن كان مرجع آخر مستخدمًا.
- لا توجد خدمة عامة غير حساسة مهيأة تلقائيًا في النسخة الحالية؛ إنشاء الجلسة لا يعني منح صلاحية لخدمة جديدة.

هذه السياسة عامة للحد من الإساءة، وليست آلية استخراج أو تسليم رموز مصادقة.

## 5) لوحة الإدارة

بعد تسجيل الدخول:

- **المخزون**: إضافة حساب/معرّف آمن، اختيار المنصة، صندوق البريد المرجعي، الحالة، والملاحظات.
- **العملاء**: عرض العملاء الإداريين المرتبطين بالطلبات القديمة.
- **الطلبات**: إنشاء مرجع داخلي وتخصيص مخزون عند الحاجة.
- **صناديق البريد**: إدارة IMAP أو ربط Outlook عبر OAuth2، واختبار قراءة فقط.
- **المنصات**: رؤية الكتالوج وحالة كل منصة وملف Steam الإداري.
- **سجل التدقيق**: إنشاء/تعديل/تفعيل/تعطيل/تخصيص العمليات الآمنة.
- **Salla**: التكامل القديم محفوظ للمراجعة الإدارية، لكنه ليس جزءًا من مسار `/salla` المحلي.

للبحث استخدم المرشح أو مربع البحث، ولا تضع أسرارًا في «الملاحظات» أو ملفات CSV.

## 6) المنصات الحالية

- **Steam**: المنصة الأساسية الموجودة في الكتالوج وتدفق العميل القديم. أي تشغيل فعلي يعتمد على إعدادات الإدارة والعينات المصرح بها.
- **Ubisoft**: مدعومة حاليًا لإدارة المخزون والتخصيص والفلترة والسجل فقط.
- **Rockstar Games**: مدعومة حاليًا لإدارة المخزون والتخصيص والفلترة والسجل فقط.

لا يوجد لـUbisoft أو Rockstar محلل بريد أو مسار عميل لعرض رموز أو بيانات اعتماد. لا تُدخل كلمة مرور أو رمزًا في المعرّف أو الملاحظات.

## 7) إضافة مخزون Ubisoft أو Rockstar

1. افتح **الإدارة → المخزون**.
2. اختر **إضافة حساب**.
3. اختر Ubisoft أو Rockstar Games.
4. أدخل معرّفًا غير حساس فقط، واختر صندوق البريد المرجعي إذا كان مطلوبًا لسجل المخزون.
5. اترك الحالة «متاح» عند الجاهزية، أو اختر «معطّل» إذا لم ترد عرضه.
6. أضف ملاحظة تشغيلية غير حساسة ثم احفظ.
7. استخدم البحث أو فلتر المنصة للتأكد من ظهوره.

## 8) معاني الحالات

- **متاح**: يمكن اختياره في عملية تخصيص آمنة.
- **مخصّص**: مرتبط بطلب إداري قائم ولا يُخصّص مرة أخرى.
- **معطّل**: محفوظ لكنه غير متاح للاختيار.
- **مؤرشف**: خارج التشغيل اليومي مع الاحتفاظ بسجل التدقيق.

## 9) Outlook

تم إعداد تطبيق Microsoft واحد لتفويض صناديق البريد. لكل صندوق سجل مستقل، ويُخزَّن Refresh Token مشفّرًا في قاعدة البيانات.

لإضافة صندوق Outlook:

1. من **صناديق البريد** اضغط «Connect Outlook».
2. سجّل الدخول في صفحة Microsoft الرسمية.
3. وافق على القراءة فقط (`Mail.Read`) والصلاحيات الأساسية اللازمة للجلسة.
4. عد إلى لوحة الإدارة وتحقق من حالة الاتصال.

لا يخزن النظام كلمة مرور Outlook. لا تنسخ Refresh Token أو Client Secret إلى الدردشة أو البريد. إذا أُلغي التفويض استخدم «إعادة التفويض» بدل إدخال كلمة مرور.

## 10) Gmail / IMAP

يبقى IMAP متاحًا للصناديق التي لا تستخدم Outlook OAuth2. يستخدم اتصال TLS وكلمة مرور تطبيق عند الحاجة، وتُحفظ بيانات الاعتماد مشفرة. صندوق Outlook OAuth2 مختلف: لا يحتاج كلمة مرور صندوق ولا يعتمد على IMAP.

## 11) Salla

تكامل Salla القديم (API وWebhook وإشعارات البريد) محفوظ ولم يُحذف. لكنه **غير مستخدم** لاتخاذ قرار فتح جلسة `/salla`. المسار الحالي لا يستدعي Salla API ولا يقرأ إشعار Salla ولا يطلب بريد المشتري؛ يكتفي بمرجع محلي غير متحقق ومعرّف عادي.

## 12) النسخ الاحتياطي

- خذ نسخة PostgreSQL قبل أي نشر أو ترقية.
- احفظ النسخة في مسار خارجي مضبوط الصلاحيات ومشفّر عند الإمكان.
- احفظ ملفات التطبيق وملفات Compose مع النسخة.
- ملف `.env` خارج التسليم ويجب ألا يُرسل علنًا.
- اختبر الاستعادة في قاعدة اختبار منفصلة، لا في الإنتاج.

## 13) VPS والخدمات

المجلد الإنتاجي: `/opt/steam-codes`.

الخدمات: `web` للواجهة وAPI، `worker` للمهام الخلفية، `postgres` لقاعدة البيانات، و`caddy` لـHTTPS. أوامر فحص آمنة:

```bash
cd /opt/steam-codes
docker compose ps
curl -fsS https://ordertrofy.store/health/live
curl -fsS https://ordertrofy.store/health/ready
```

لإعادة تشغيل الخدمة بعد موافقة النشر:

```bash
docker compose up -d web worker caddy
```

اعرض السجل بعد تنقيته ولا تنسخ السطر كاملًا إذا احتوى قيمة حساسة:

```bash
docker compose logs --since 15m web worker
```

## 14) النشر والتراجع

1. خذ نسخة احتياطية وتحقق من توفر مساحة القرص.
2. راجع التغيير والاختبارات.
3. نفّذ `docker compose run --rm web alembic upgrade head` عند وجود migration.
4. أعد تشغيل `web` و`worker` فقط، و`caddy` إذا تغيرت إعداداته.
5. تحقق من health endpoints والصفحة المتأثرة.
6. عند مشكلة، أوقف الإصدار الجديد وأعد صورة Docker السابقة بعد حفظ السجل المنقح.

## 15) قاعدة البيانات وAlembic

الرأس الحالي للمخطط هو `20261004_0009` (كتالوج المنصات الآمن). افحصه دون كشف بيانات:

```bash
docker compose run --rm web alembic current
docker compose run --rm web alembic heads
```

لا تحذف جداول الإنتاج ولا تنفذ downgrade غير مختبر.

## 16) حل المشاكل

| المشكلة | ما الذي تفحصه | الحل الآمن |
|---|---|---|
| الحقول لا تظهر على الهاتف | الرابط `/salla`، عرض الهاتف، وعدم وجود تمرير أفقي | حدّث الصفحة بذاكرة CSS جديدة وتحقق من `/health/ready`؛ لا تغيّر قاعدة البيانات |
| Outlook غير متصل | حالة الصندوق وسجل `last_error_code` | استخدم إعادة تفويض Microsoft الرسمية، ولا تلصق كلمة المرور أو التوكن |
| فشل Mail.Read | صلاحية `Mail.Read` وصحة OAuth | أعد التفويض بصلاحية القراءة فقط وافحص الرسالة الاختبارية غير الحساسة |
| العامل متوقف | `docker compose ps worker` وhealth | أعد تشغيل `worker` بعد فحص السجل المنقح |
| health يفشل | حالة `web` و`postgres` | افحص `docker compose ps` والاتصال بقاعدة البيانات |
| قاعدة البيانات غير متاحة | حالة `postgres` وسجل الاتصال | لا تعِد إنشاء قاعدة الإنتاج؛ أصلح الشبكة/الحاوية وخذ نسخة أولًا |
| اختلاف migration | `alembic current` مقابل `heads` | نفّذ migration الموثق فقط ثم تحقق من readiness |
| انتهت حصة المرجع | العداد والمهلة الظاهرة | انتظر نافذة 24 ساعة أو استخدم مرجعًا مستقلًا معتمدًا من المتجر |
| الحساب معطّل | حالة المنصة/الحساب في المخزون | فعّله فقط بعد التحقق الإداري من البيانات غير الحساسة |

لا يوجد في هذا الدليل تشخيص لاستخراج أو تسليم رموز دخول.

## 17) قواعد الأمان

- لا ترسل كلمات المرور في مستقل أو WhatsApp.
- لا ترسل لقطات Client Secret أو Webhook Secret.
- لا ترسل `.env` أو نسخة قاعدة بيانات خاصة.
- دوّر أي سر تم كشفه، مع تحديث الطرفين في نفس الوقت.
- استخدم OAuth الرسمي حيثما كان متاحًا.
- خذ نسخة احتياطية قبل تغيير كبير.
- لا تضع رموز مصادقة أو كلمات مرور في المعرّفات أو الملاحظات أو السجل.

## 18) قائمة الصيانة

**يوميًا:** فحص `health/live` و`health/ready`.

**أسبوعيًا:** التحقق من نسخة احتياطية، مراجعة أخطاء مختصرة، ومساحة القرص.

**شهريًا:** تحديثات الحزم الأمنية، حذف الصناديق/الحسابات غير المستخدمة بعد مراجعة، ومراجعة سجل التدقيق.

## 19) عند إضافة مخزون

1. افتح المخزون.
2. اختر المنصة.
3. أدخل معرّفًا غير حساس فقط.
4. اختر صندوقًا/حالة صحيحة.
5. احفظ.
6. ابحث عن السجل وتحقق من الحالة.
7. لا تضع كلمة مرور أو رمزًا في أي حقل.

## 20) ما يحتاجه المطور مستقبلًا

المكدس FastAPI + Jinja2 + SQLAlchemy async + PostgreSQL + Alembic + Docker Compose. أهم المجلدات: `app/main.py` للمسارات، `app/models.py` للنماذج، `app/services/` للخدمات، `app/mail/` للبريد، `app/web/templates/` للقوالب، `app/static/` للتنسيق، `alembic/` للترحيلات، و`tests/` للاختبارات.

أي خدمة جديدة يجب أن تكون غير حساسة ومراجعة قبل ربطها بسياسة الاستخدام. لا تُنشئ محللًا لرموز مصادقة.

## 21) أسماء متغيرات البيئة

`APP_ENV`, `APP_SECRET_KEY`, `DATABASE_URL`, `DATABASE_URL_SYNC`, `MAIL_CREDENTIALS_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_WEBHOOK_URL`, `PUBLIC_BASE_URL`, `COOKIE_SECURE`, `CADDY_DOMAIN`, `IMAP_LABEL`, `IMAP_HOST`, `IMAP_PORT`, `IMAP_USERNAME`, `IMAP_PASSWORD`, `MICROSOFT_CLIENT_ID` أو `MICROSOFT_OAUTH_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` أو `MICROSOFT_OAUTH_CLIENT_SECRET`, `MICROSOFT_AUTHORITY` أو `MICROSOFT_OAUTH_TENANT`, `MICROSOFT_REDIRECT_URI` أو `MICROSOFT_OAUTH_REDIRECT_URI`, `SALLA_CLIENT_ID`, `SALLA_CLIENT_SECRET`, `SALLA_WEBHOOK_SECRET`, `SALLA_TOKEN_KEY`, `SALLA_APP_ID`, `SALLA_API_VERIFICATION_ENABLED`, `SALLA_NOTIFICATION_POLL_SECONDS`, `SALLA_CUSTOMER_SESSION_MINUTES`, `SALLA_USAGE_MAX`, `SALLA_USAGE_PERIOD_SECONDS`, `SALLA_USAGE_COOLDOWN_SECONDS`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`.

هذه أسماء فقط؛ لا تحفظ القيم في المستودع أو الوثائق.

## 22) حدود معروفة

- رقم الطلب في `/salla` مرجع محلي غير متحقق عبر Salla.
- لا توجد خدمة عامة غير حساسة مفعّلة تلقائيًا.
- Ubisoft وRockstar إدارة مخزون فقط، وليستا تدفق مصادقة.
- Salla API وإشعارات البريد محفوظة للتوافق والإدارة وليست شرطًا للمسار المحلي.
- يلزم اختبار عينة مصرح بها لأي قالب بريد إداري قبل اعتماده.
- النسخ الاحتياطي يحتاج تجربة استعادة دورية.

## 23) إذا نسيت كل شيء

1. افتح `https://ordertrofy.store/salla`.
2. اكتب رقم الطلب كمرجع محلي.
3. اكتب المعرّف.
4. اضغط «متابعة».
5. إذا ظهرت مشكلة: افحص `/health/ready` ثم راجع لوحة الإدارة والسجل المنقح.
6. لا ترسل أي كلمة مرور أو سر أو رمز مصادقة.

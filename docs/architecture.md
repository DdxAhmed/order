# المعمارية

التطبيق Modular Monolith بثلاث عمليات: `web` للبوابة العامة ولوحة الإدارة وWebhook الاختياري، و`worker` للبحث في البريد، وPostgreSQL للحالة والطابور والقيود. لا توجد حالة أمان في ذاكرة عملية Python فقط.

```text
مدير → لوحة RTL → FastAPI → PostgreSQL ← Worker ← IMAP TLS
عميل → رابط موحد + رقم الطلب وUser Steam → هوية استخدام محلية غير مُتحقق منها → جلسة ويب HttpOnly → PostgreSQL → بوابة العميل
Telegram (اختياري) → Webhook → FastAPI → PostgreSQL → Worker
```

## مسار الوصول المحلي ومسارات Salla المنفصلة

يعمل `/salla` و`/api/integrations/salla/webhook` كمسارين منفصلين تمامًا. ينشئ `/salla` هوية استخدام محلية من رقم الطلب الذي يقدمه العميل ومن alias اختياري/مطلوب بحسب النموذج. الرقم مرجع خارجي غير مُتحقق منه، ولا يستدعي هذا المسار Salla API ولا يقرأ إشعارات البريد ولا يطلب بريد المشتري ولا يحتاج تسجيلًا مسبقًا. لا توجد في هذا المسار تسمية «طلب موثّق».

تُحفظ هوية المرجع محليًا، وتُقفل عدادات الخدمات المسموح بها على PostgreSQL: خمسة استخدامات في 24 ساعة متحركة لكل مرجع وخدمة، مهلة 30 ثانية، وidempotency للطلبات المكررة. حدود الجلسة وIP طبقة إضافية لمنع الإساءة. تبقى جداول Salla وWebhook واستيراد البريد محفوظة لتكاملات الإدارة والتوافق، لكنها لا تُستدعى لاتخاذ قرار فتح جلسة الوصول المحلي.

يبقى API المباشر خلف feature flag `SALLA_API_VERIFICATION_ENABLED=false` افتراضيًا إلى أن تكتمل مراجعة التطبيق. يحتاج Easy Mode إلى تثبيت التطبيق من التاجر وتفعيل حدث `app.store.authorize` في Partner Portal. انتهاء Access Token يعيد استخدام Refresh Token مرة واحدة داخل قفل صف؛ الفشل يتطلب إعادة التفويض. لا يتم تسجيل التوكنات، ولا تُعاد أي بيانات عميل حساسة إلى المتصفح. هذا التكامل لا يضيف أو يوسّع أي استخراج أو عرض أو تسليم لرموز مصادقة الألعاب.

## حدود الثقة

- جلسة العميل تُصدر بعد تحقق الصيغة وإنشاء/استرجاع هوية المرجع المحلي؛ تُخزن تجزئة الجلسة فقط. المرجع ليس إثبات ملكية لطلب Salla، والطلبات العامة محدودة عبر Rate Limit ولا تكشف وجود مرجع لمستخدم آخر.
- كل طلب تحقق يثبت إما على جلسة ويب للعميل أو Telegram user ID اختياريًا، وليس كليهما.
- اسم الحساب/المعرّف بيانات وصفية عادية غير حساسة، وليس إثباتًا لملكية طلب أو حساب خارجي.
- بيانات IMAP مشفرة بمفتاح `MAIL_CREDENTIALS_KEY` الخارجي. لا يسجل النظام كلمة المرور أو نص الرسالة أو الرمز.
- مدير المالك وحده يغير صناديق البريد وملف Steam. المشغل يدير المخزون والطلبات، والمدقق للقراءة فقط.

## التزامن

- تخصيص الحساب يستخدم صفوفًا مقفلة وفهارس جزئية تمنع تخصيصًا نشطًا ثانيًا.
- رمز التفعيل يقفل صفه ويصبح مستخدمًا في المعاملة نفسها التي تصدر جلسة الويب.
- طلب تحقق نشط واحد لكل تخصيص، ومطالبة بريد فريدة بحسب صندوق البريد وUIDVALIDITY وUID.
- الطابور PostgreSQL يعتمد `FOR UPDATE SKIP LOCKED` وlease؛ المهام المنتهية lease قابلة للاسترداد.

## Steam

`SteamMailAdapter` لا يقبل رسالة ما لم تتحقق كل الشروط: نطاق مرسل مهيأ، Authentication-Results مهيأ، تطابق حساب كامل، رمز وحيد، حد زمني، و`sample_verified_at`. لا توجد افتراضات مخفية حول قالب Steam أو API غير موثق.

## Ubisoft وRockstar Games

تظهر المنصتان في كتالوج المنصات وإدارة المخزون والتخصيص والفلاتر والاستيراد. حقولهما عامة (`platform`, `identifier`, `status`, `notes`) ولا تخزن كلمات مرور أو أسرارًا. لا يوجد لهما adapter بريد أو محلل رسالة أو مسار عميل لتسليم رموز؛ أي دعم بريد مستقبلي يقتصر على metadata غير حساسة مثل النطاق والتصنيف والتوقيت.

## Outlook OAuth2

صناديق البريد تدعم IMAP بكلمة مرور تطبيق، أو Microsoft Graph بتطبيق واحد لكل الصناديق وصلاحيات OAuth2 delegated `openid profile email offline_access Mail.Read` فقط. الحسابات الشخصية تستخدم authority `consumers`. تدفق الربط وإعادة التفويض يبدأان من لوحة المالك بحالة عشوائية أحادية الاستخدام، ثم تُحفظ Refresh Token مشفرة بمفتاح بيانات البريد. العامل يقرأ الرسائل عبر Graph قراءةً فقط، ويحفظ أي Refresh Token جديد يعيده Microsoft، ولا يسجل التوكن أو محتوى الرسالة.
